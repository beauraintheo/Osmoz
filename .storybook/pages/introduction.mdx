# One behavior. Many identities.

Every Osmoz component is written once, without a single class: its
element, its keyboard, its ARIA states. Each app then gives it its own look,
from its own tokens. This Storybook shows both halves.

## Four principles

1. **Base UI first, native otherwise.** Each component wraps its
   [Base UI](https://base-ui.com) counterpart, which brings keyboard, focus
   and ARIA. Where Base UI has none, it builds on the native element.
2. **Behavior shared, look owned.** `@osmoz/ui` ships no class. Each app wraps
   every component in its own `components/ui/`, with its tokens.
3. **Texts come from the app.** A shared component writes no user-facing word.
   Every label is a prop, read from the app's catalog, in its language.
4. **AA in every theme.** WCAG 2.2 AA is the floor: contrast, visible focus,
   opt-in motion, 24 px targets, everything by keyboard.

## How to read this Storybook

| Section    | What it shows                                                                                                                                                                                             |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Osmoz**  | Why the design system exists and how to use it, these pages and the brand, then each component bare: the contract, its states, the DOM they produce, its keyboard. An interaction test checks each claim. |
| **An app** | The same components dressed by one app, in its theme. The toolbar's theme button switches every page.                                                                                                     |

Behavior lives in `@osmoz/ui`, the mark in `@osmoz/brand`, the looks in each
app.
