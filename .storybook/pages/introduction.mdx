# One behavior. Many identities.

Every Osmoz component is written once, without a single class: a native
element, its keyboard, its ARIA states. Each app then gives it its own look,
from its own tokens. This Storybook shows both halves.

<Canvas of={UiButtonStories.Pending} />

The same pending button, as the contract ships it: no class, only the
`aria-busy` it sets. Each app styles it in its own section.

## Four principles

1. **Native elements first.** A `<button>` before a div with a role. A
   headless library comes in only where no native element fits.
2. **Behavior shared, look owned.** `@osmoz/ui` ships no class. Each app wraps
   every component in its own `components/ui/`, with its tokens.
3. **Texts come from the app.** A shared component writes no user-facing word.
   Every label is a prop, read from the app's catalog, in its language.
4. **AA in every theme.** WCAG 2.2 AA is the floor: contrast, visible focus,
   opt-in motion, 24 px targets, everything by keyboard.
