# IconButton

A `Button` whose action is shown by an icon alone. It requires a text `label`,
which becomes its accessible name, and hides the icon from assistive
technologies, so a screen reader announces "Undo, button" and not an unnamed
graphic.

## Usage

<Guidelines>
  <Guideline

    Undo, redo, help, reset a property.

  </Guideline>

  </Guideline>

## States

Each card renders its story and lists the attributes read on the rendered
`<button>`.

<States>
  <State of={IconButtonStories.Default}>Focusable. Click runs.</State>
  <State of={IconButtonStories.Disabled}>`disabled`. Skipped by Tab. Click blocked.</State>
  <State of={IconButtonStories.Pending}>`pending`. Focusable. Click blocked.</State>
</States>

`IconButton` renders a `Button`, so it has every state of `Button`, including
**disabled but focusable** (`focusableWhenDisabled`), documented on its page.
In every state, the accessible name stays the `label`.

## Keyboard

<Keyboard>
  <Key keys={["Tab"]}>Moves the focus to the button, unless it is `disabled`.</Key>
  <Key keys={["Enter", "Space"]}>Runs the action, unless the button is disabled or pending.</Key>
</Keyboard>

## Accessibility

- The accessible name is `label`, set as `aria-label`. The app passes it from
  its catalog.
- `label` is required and `aria-label` and `children` are not props: the name
  cannot be left out or overridden.
- The icon is wrapped in `<span aria-hidden="true">`: it is never announced.

## Styling

The component has no class. Each app styles it in its own
`components/ui/icon-button.tsx`: a square size for the button and its icon, and
the same state classes as `Button` (`disabled:`, `aria-disabled:`,
`aria-busy:`, `focus-visible:`). See each app's section of this Storybook for
its look.

The roles of the contract a styled icon button maps to, with their values in
the Osmoz theme of this page, not of an app:
